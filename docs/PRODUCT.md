# 产品定义

> 本文回答「foldercast 是什么、给谁用、不做什么」。这是所有设计决策的上位依据，改动需走 [decisions/](decisions/) 的 ADR 流程。

---

## 一句话

**foldercast 把任意一个人类可读的目录，变成一段（或多段）讲解视频。**

```
目录  ──►  视频
```

---

## 问题

一个目录里通常混着这些东西：

| 内容 | 例子 |
|---|---|
| 代码 | `.ts` / `.py` / `.go` |
| 可编辑文本 | `.md` / `.txt` / `.tex` |
| 图片 | `.png` / `.jpg` / `.svg` |
| 视频 | `.mp4` / `.mov` |
| 办公文档 | `.docx` / `.xlsx` / `.pptx` / `.pdf` |

你想让**别人**（或三个月后的**自己**）快速理解它。现状是：

- **写文档太慢**：写一份能讲清楚的 README 要几小时，而且没人读。
- **录屏太累**：手动录屏要一边操作一边讲，口误就得重来。
- **现有工具不匹配**：`paperview` / `gitreel` / `explainmyrepo` 都只吃 **git 仓库**。

而现实中大量值得讲清楚的目录**根本不是 git 仓库**：资料整理、课程材料、汇报素材、混合工作区。

---

## 目标用户与场景

| 场景 | 产物 | 观看者 |
|---|---|---|
| 项目介绍 | 一段 3 分钟导览 | 别人 |
| 成果汇报 | 一段 5 分钟讲解 | 上级 / 同事 |
| 资料整理 | 一段目录说明 | 未来的自己 |
| 一次性理解 | 看完就删的短视频 | 自己 |

「给自己看的一次性视频」是**一等场景**，不是副产品。它意味着工具必须支持**低成本、可快速出片**，而不是每次都追求发布级质量。

---

## 输入定义的边界

「人类可读」是准入线，不是技能线。判据：

> 如果一个人打开这个目录、逐个文件看下去，能理解它在讲什么 —— 那它就能被 cast。

**是**：

- 代码仓库、文档目录、资料合集
- 混合工作区（多个项目并列）
- 课程材料、汇报素材、设计稿目录

**不是**（或意义不大）：

- 纯二进制产物目录（`dist/`、`build/`）
- 依赖目录（`node_modules/`）
- 数据集目录（几万个 `.csv`，内容同质）
- 空目录

后三类由默认排除规则处理，见 [SPEC-data-format.md](specs/SPEC-data-format.md)。

## 核心设计立场

### 1. 目录 ≠ 仓库

这是与所有竞品的分界线。不假设 `git` 存在，不读 commit 历史，不做 diff。只看**目录里现在有什么**。

### 2. 三步管线：文案 → 视频 → 配音

固定顺序，不可调换。详见 [specs/SPEC-pipeline.md](specs/SPEC-pipeline.md)。

配音放最后是因为：文案和画面是创作（迭代频繁、无外部依赖），配音是渲染（有 API 成本、可换音色）。反过来会让每次改稿都触发一次 TTS 调用。

### 3. 解读是事实来源，讲稿是它的视图

`foldercast.json`（目录解读）由程序产出，可重算；`script.json`（讲稿）由叙事层或人产出，是创作。
渲染器只读 `script.json` 与素材，配音只读它。想改片子？改讲稿，不改代码。

**一份解读可以配多份讲稿** —— 讲给同事的、讲给三个月后自己的，共用同一份分析结果。

### 4. 管线分两层：事实层确定，叙事层通读

事实层（遍历、分类、统计、引用关系）是程序，可复现；叙事层（讲什么、什么顺序）是 Agent 集群，会通读文件内容。
分析器不调用模型，理由是可复现与成本，**不是隐私**（[ADR 0006](decisions/0006-narration-layer-moves-up.md)）。

唯一的读取例外是密钥类文件（[ADR 0007](decisions/0007-secret-file-exclusion.md)）。

### 5. 风格既管画面，也管语气

只改配色的"风格"是半成品。同一份目录用讲解型/导览型/汇报型语气讲，讲稿完全不同。
所以风格包含 `narration.*` token 并参与写稿提示词。

### 6. 容器型目录必须出多个视频

很多目录本身就是「项目的容器」（工作区里并列多个项目）。对这种输入，出一份讲稿是错的 —— 讲不清全貌也讲不清细节。

正确产物：1 个总览 + N 个项目视频。

### 7. 不做 HTML 中间层

Remotion 本身就是 HTML 渲染器（无头浏览器逐帧截图）。先做 HTML 再转视频 = 渲染两遍、动效写两遍。

## 非目标

明确不做，避免范围蔓延。**若要做，需先写 ADR 推翻。**

| 不做 | 原因 |
|---|---|
| 网页/文档形态产物 | 只出视频。要网页应该用别的工具 |
| 文生视频素材（AI 生成画面） | 我们是「讲清已有内容」，不是「凭空画」 |
| PR / diff 影评短片 | `gitreel` 的地盘 |
| 竖版短视频营销号 | `demo-reel` 的地盘 |
| 云端服务 / SaaS | 本地工具。**注意：这不等于内容不出机器**，叙事层会把内容送进模型上下文（ADR 0006） |
| 交互式 Web UI（MVP） | 配置文件即可 |
| 实时预览编辑 | Remotion Studio 已提供 |
| 与 `lecture-videos` 共享代码 | 独立项目，独立演进 |

## 成功判据

MVP 完成的标志（不是 star 数）：

1. 对三种真实目录各跑通一次，**全程不需要改代码**
   - 单一代码项目
   - 混杂资料目录
   - 含 Office 文档的汇报目录
2. 换 TTS 音色**只需重跑第三步**
3. 同一份分镜渲染两次，输出**逐帧一致**
4. 自然语言风格描述能被解析，解析不了的**明确报错**而非静默忽略

验收细节见 [ROADMAP.md](ROADMAP.md)。
