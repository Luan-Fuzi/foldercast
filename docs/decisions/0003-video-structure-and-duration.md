# 0003 · 视频结构与时长规划：总-分-总，时长由内容量决定

日期：2026-10-08　状态：生效　关联：0001（最小 agent 插件）

## 背景

0.1 的自举样片（64.85 秒）实测暴露两个产品问题：一是结构「有分无总」——开头只有
一句封面、结尾只有一句谢幕，没有全貌交代也没有结构收束；二是时长拍脑袋——写稿时
默认了「七场、每场一句」，一分钟根本讲不清一个上万行的项目。

## 决定

1. **结构固定为「总—分—总」**：cover 后先有一两场全貌判断（是什么、分几大块、
   块之间什么关系），中间分模块按逻辑顺序展开，最后一场回顾结构收束。写进 skill
   （工作流判据），不是代码——结构是创作判断，程序管不了。
2. **时长由内容量决定，不预设**：先量（代码行数、文档字数、文件数——写稿 agent
   反正要数），按量级表拟目标（小型 3–4 分钟 / 中型 5–8 分钟 / 大型 8–15 分钟），
   写进 `video.targetDurationSec`，再按目标规划场景与旁白量。量级表是**起点**，
   调整要有理由；讲清比凑数重要。
3. **校验器补闭环**（这是代码）：讲稿写了 `targetDurationSec` 时，`--check` 比较
   「按旁白量预估的时长」与目标，偏差超过 ±35% 报 warning。旁白量才是真正的时长
   旋钮（配音后成片时长由实测音频决定），预估-目标闭环让「拟时长→写稿」不会脱节。

## 边界

- `targetDurationSec` 仍是软约束：无配音时渲染按它缩放场景；有配音时实测为准。
  不在渲染层强行拉长或截断——画面跟着声音走，不反过来。
- 不给「每个项目至少 N 分钟」的硬下限：下限由「总分总三段都立得住」自然产生。
