# 0007 · 评审先于产出：产物在质量闸门之后，顺序由 skill 驱动

日期：2026-10-09　状态：已实施　关联：0001（程序不替模型干活）、0004（两阶段创作与评审）

## 背景

原流程里 `page.html` 挂在校验阶段「顺手产出」：讲稿过机器校验就立即落一份用户可见的
导览页，然后才轮到评审。自举仓库的一次实况暴露了问题——评审**总判定不通过**
（compare 场画面上一行数字与事实不符），写稿 agent 随后改稿；但按旧流程，带着那行
编造数字的 `page.html` 在评审之前就已经产出过一版，成了（可能已被看过的）过期产物。

诊断：**校验和评审是两道闸门，产物一道都没过。** 机器校验拦的是形状错误（编造路径、
字段用错）；模型评审拦的是内容错误（事实、重点、结构）。HTML 与视频都是**产物**，
产物必须在两道闸门之后。

## 决定

1. **评审先于一切产出，且评审是个环**。流程定为：探目录 → digest → 定场景 → 写稿 →
   校验（机器，只给结论、不落文件）→ 评审（模型，两段式）→ **不通过则修正 → 复评**，
   末轮通过才产出。修正按轻重分级：轻问题改讲稿，重问题（重点错、结构烂、编造成片）
   回头重塑 digest——打补丁修不了选材错误。复评不可省：核对上轮问题确实修了 + 抽查
   改动处没引入新错（正是自举那次暴露的缺口：改完不复评，放行全凭自觉）。评审通过
   之前，用户可见的东西一件不产。中途想看画面可以独立跑 \`pnpm page\`——那是工作草稿，
   不是产物。
2. **产出顺序由 skill 驱动，不焊死在工具里**。工具只暴露正交开关：\`page\` / \`render\` /
   \`voice\`（一次调用都传时按 check → page → voice → render 执行）。默认编排写进 skill：
   **先 HTML 再视频**（两者是同一份讲稿的两个出口，HTML 秒级且是视频画面的忠实预览，
   0006）；**用户只要 HTML 就停在 HTML**，不顺手渲片；用户要过视频就出全。
3. **人类的中途检查点没有丢，只是移位**：从「校验后」移到「评审后、渲染前」——评审
   是读文件的分钟级操作，远便宜于渲染；用户仍然在贵的步骤之前拿到便宜的可视检查物。
4. **产物状态不变量**：产出发生时，\`digest.json\` 是被审过的事实库、\`script.json\` 通过了
   末轮评审、\`review.md\` 末轮为「通过」、\`page.html\` 与 \`video.mp4\` 由这份通过的版本渲出；
   讲稿一改旧产物即刻作废。评审轮次上限两三轮，超了把分歧如实报给用户裁决——用户的
   判断优先于评审的判断。

## 改动面

- `src/cast.ts`：page 阶段改为 `page: true` 显式触发（原来是有讲稿且 blocker 为 0 就自动跑）。
- `src/index.ts`：工具参数加 `page`，description 与输出 schema 的措辞同步（「校验只给
  结论，产物显式要」）。
- `src/skill.ts`：第五步改为「校验并修（只给结论，不产出）」；第七步改为「产出（先
  HTML，再按需出片）」，写明 HTML-only 与默认出全两种编排；工作流总述加「评审通过
  之前不产出任何用户可见的东西」。
- `src/tests/tool.test.ts`：断言翻转——校验通过时 `ran = ['check']`、无 page.html；
  传 `page: true` 才产出导览页。

## 边界

- 「顺手产出」原设计的一个真实收益（校验阶段免费拿一页预览）被放弃：评审不慢，
  预览晚几分钟出现换「产物永远是被审过的版本」，划算。
- `pnpm page` 直跑入口不变；它产出的文件与工具产出的同一份，只是不承诺评审状态。
