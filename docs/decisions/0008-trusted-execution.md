# 0008 · 模型创作与可信执行

日期：2026-10-10　状态：已实施　关联：0001、0004、0005、0007

## 问题

「程序只做 agent 干不了的事」避免了用分析器替代模型理解，但把版本一致性和缓存依赖也交给模型记忆。原流程中的评审通过是 skill 约定，工具无法确认报告对应哪一版讲稿；音频主要按文件存在性复用。页面与视频共享场景卡，却有不同的素材准备路径。

## 决定

模型负责理解、判断与创作；程序负责精确、重复、可复现和可验证的执行。程序可以提供统计和原文提取能力，但不接管选材与叙事。本决定调整 0001 的责任划分，保留最小插件与模型编排的方向。

### 版本、回执与草稿

校验返回 revision：script、在场的 digest 和直接引用文件使用内容哈希；引用目录使用文件名、大小与修改时间，不读取其全部正文。digest 在场时，文件总数抽查结果也参与 revision。它不覆盖整个源目录的正文，也不绑定软件或渲染器版本。独立评审仍由模型执行，结论与证据写入 review.md。末轮通过后，主 agent 传 reviewRevision 记录 review.json 回执；传参表示主 agent 声明评审通过。工具检查版本匹配与报告存在并绑定报告哈希，不解析自然语言结论；正式产出还检查报告哈希未变。

正式 page / voice / render 要求当前输入与评审回执相匹配。draft: true 允许未评审的工作草稿。直接运行 CLI 默认草稿，--approved 要求回执。修改讲稿、digest 或引用文件后需重新校验与复评。程序能确认报告与当前输入版本一致，不能证明报告正确，也不能证明模型执行了独立评审。

自定义输出不能覆盖引用证据或落入引用目录；digest 在场时，不能写到源目录的 .foldercast 之外，防止生成文件改变文件总数。在写出前检查此约束。建议放在 .foldercast/out 中或源目录之外。旧产物引用的自定义讲稿缺失时，状态标为过期，不阻断当前任务。

artifacts.json 记录产物的输入版本、实际参数、文件依赖与输出哈希。current 表示仍匹配记录中的输入与参数，不证明内容正确，也不表示适合新的设置。输入改变不会自动重做产物，旧文件的存在不能当作当前版本的交付依据。

### 音频依赖

audio/cache.json 逐场保存合成请求哈希与音频哈希，关联旁白、provider、音色、风格和格式。每场完成后写回，失败后可断点续跑。输入变化自动使缓存失效；forceVoice 保留为主动重配选项。时长与字幕仍从有效音频计算。只改画面不需要重合成；改讲稿中的 voice 配置需重跑 voice，但实际请求相同的场景可以复用。渲染拒绝过期、缺少新版本记录或整条音轨不完整的 durations；校验不消费配音缓存，改稿后可先校验与复评再配音。

### 共享场景数据

HTML 与视频使用相同素材准备与场景数据，再由场景卡适配静态页面或视频时间轴。复用内容、来源与素材，不承诺像素相同。页面仍有图片内联预算，超过预算使用相对路径。Office / PDF 页图与视频封面引用的是准备产物，不是原 PDF 或视频；转发时需携带被引用文件并保持相对位置。不强制所有结果单文件转发。

### skill 与参考

主 skill 保留目标、探索、两阶段创作、校验、独立评审与复评、回执及显式产出。场景字段和详细评审判据按需读取随包 references。契约版本与字幕宽度从代码常量插值，避免提示词另维护版本。

digest 深度围绕本次目标，不强制全量富集。本次不新增 claims 或其他 schema 字段。总—分—总、代码量估时、8–12 行摘录和 1.5–3 密度比是默认建议；warning 由模型结合目标判断。事实、推断与未知应保留其确定程度。

## 兼容与迁移

讲稿与 digest 的 schema 版本不变。旧 review.md 没有版本回执，需重新评审当前输入并记录 review.json。旧音频缺少逐场缓存记录，第一次重跑 voice 会重新合成；旧 durations 缺少新增版本记录，不能直接用于渲染。之后按实际合成请求复用音频，不需要删除整个工作目录。

## 范围与验证

本次不增加工作流平台、不替换渲染引擎、不实现浏览器溢出自动检查。机器检查版本、契约与文件依赖；内容质量、听感、视觉重点仍需模型或人工判断。验证重点是版本变化阻止旧回执、旁白或合成输入变化使音频缓存失效，以及两种输出共享素材路径。

2026-10-10 本地验证：`pnpm typecheck`、`pnpm run check`、插件 `prepack` 与 `git diff --check` 通过。修正 Vitest 的串行配置后，`pnpm test`：31 个测试文件通过，278 项通过、2 项按环境分支跳过。验证包含真实 PDF 页图、视频渲染与画面基线；TTS 使用离线 fake provider，未进行真实合成或听感验收。编译后的正式页面入口、评审回执与产物状态也已验证。
