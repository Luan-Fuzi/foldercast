# 0009 · 共用美术预设与自定义创作提示词

日期：2026-10-11　状态：已实施　关联：0006、0008

风格名称与内置创作指导现按 [0011](0011-semantic-style-names.md) 更新；下文保留本次实施时的名称。

实际设置页中的配音引擎和页面风格都是自由文本，默认音色名称不可见。视频固定使用素稿，页面的杂志与夜幕预设无法用于视频。用户要求下拉选择、其他美术风格，以及引导整体视觉与创作的自定义提示词。

## 决定

美术预设由程序执行，自定义提示词由模型理解并落实到场景设计、选材、重点和节拍。预设先提供瑞士（内部标识仍为素稿）、杂志和夜幕，复用现有色板和系统字体，不引入自由 HTML/CSS 或自然语言到 CSS 的猜测程序。

设置新增 visual.style 与 visual.prompt。创作前 foldercast_cast 返回当前 visualPreferences；模型结合用户当前要求，将本次采用值写入讲稿的 visual。讲稿中的风格优先于插件默认值，直接 CLI 的 --style 可显式覆盖。visual 是 script v2 的可选字段，参与现有 revision，改动后旧回执失效。提示词不由渲染器执行，已有讲稿不会因设置变化而自动改写。

视频与默认 HTML 采用同一美术预设，代码高亮随深浅底切换。原 page.style 保留为页面的独立覆盖；新默认为跟随整体美术风格。旧讲稿缺少 visual 时使用设置页默认值；未另设默认值或直接使用 CLI 时保持素稿，不需迁移 schema 版本。实际风格参数进入 artifacts.json，旧产物不会自动重做。

设置页按美术与创作、配音、高级设置组织。配音引擎、音色和美术预设使用下拉控件；音色保留自定义入口，切换引擎时清除上一个引擎的音色。edge 下禁用朗读风格。用户覆盖投影只在字段确实存在时写入键，修复缺失字段被标为已覆盖的问题。

## 边界

这次提供可复现的色板、字体和卡片观感变化，场景仍为现有 11 种。提示词不能直接生成任意新布局；创作质量需通过独立评审和目检确认。美术变化不改变旁白时，仍可复用有效音频。

## 本机验证

在 DeepSeek Harness 的真实设置页检查了预置音色、自定义音色入口，以及切换 Mimo 后默认音色和朗读风格控件的联动。临时选择已恢复，未保存用户配置。

同一份检查讲稿分别生成了三套预设的静帧与 HTML，均成功。静帧目检发现视频容器未设置正文颜色，导致夜幕的标题、文件名与要点仍为黑色；补上共用 ink 变量后再次渲染，确认浅色文字与深色代码高亮正常。

类型检查、分发构建与文档检查通过。全量测试中 284 项通过、2 项跳过；正文色变化使本机画面基线比较失败。独立重渲并目检代码与 Markdown 两张基线图，确认哈希与全量测试一致后更新了本机基线；随后基线、高亮和配置回归的 17 项测试全部通过。
