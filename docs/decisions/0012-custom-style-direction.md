# 0012 · 自定义风格作为创作指导

日期：2026-10-11　状态：已实施　关联：0009、0011

用户要求增加「自定义风格」，自己描述希望的效果，再将描述注入创作提示词。已有预设附加提示词仍容易被理解为仅对现有风格作微调，需要明确的自定义选择。

## 决定

整体美术风格增加「自定义风格」。选中后展示可选名称、基础视觉预设与「想要的效果」。名称留空使用「自定义风格」；效果描述为空时，设置页给出提示并禁用保存。沿用已有的 `visual.prompt` 保存效果，新增 `visual.customName` 和 `visual.customBaseStyle`，不复制一份描述字段。切换回内置风格保留字段值，未启用的名称与基础预设不进入该风格的创作指导。

工具的 `visualPreferences` 在自定义模式返回 `style: "自定义风格"`、`name`、`baseStyle`、`stylePrompt` 和可选的原始 `prompt`。`stylePrompt` 包含用户名称与效果描述；基础预设的内置创作指导不附加进来。手动配置缺少描述时，工具明确说明缺项，模型先利用当前对话，只有无法判断且影响取舍时再询问，不能静默替换成内置创作风格。

讲稿保留 `visual.style: "自定义风格"`、可选 `name`、`baseStyle` 和非空 `prompt`。schema 继续使用版本 2，校验自定义风格必须有非空描述。名称与效果属于讲稿内容，参与现有 revision；已有讲稿不会自动改写。

页面和视频从 `baseStyle` 解析实际视觉预设，缺省瑞士风格；用户描述由写稿模型落实到选材、场景组织和节拍。明确的页面单独风格或 CLI `--style` 仍可覆盖实际画面预设，不改写自定义名称和描述。

## 边界

本次提供一套自定义风格设置，不增加多套风格的保存和管理，也不把自然语言转为任意 CSS、字体或布局。模型创作仍使用现有 11 种场景，实际视觉参数由基础预设决定。设置页与主 skill 明确这项限制，避免将描述注入误认为自由版式渲染已经实现。

## 验证

`pnpm typecheck`、`pnpm run check` 和插件 `prepack` 通过。相关 7 个测试文件的 80 项测试通过，覆盖设置解析、工具返回、自定义讲稿校验、渲染计划和实际 HTML 输出。另用自定义讲稿通过真实浏览器生成视频静帧，临时产物已删除。

本次未做真实 Agent 创作质量评估，也未在 Harness 中目检新设置页。Harness 存在用户未保存的设置，未重启或覆盖这些设置；新入口和设置页已构建，重启后加载。
