# 0.3.1 发布计划

状态：0.3.1-rc.1 已发布，真实 DSH 创作与正式产出检查通过，待用户确认整片播放与听感后准备正式 0.3.1。目标：修复引用边界与 HTML 交付，补齐许可、对外介绍和可复现的发布流程。

## 发布范围

1. 引用路径共用检查：讲稿、digest、revision、素材准备；阻止绝对路径、目录穿越与目录外符号链接。
2. HTML：程序生成的说明不带本机绝对路径，窄屏无整页溢出，分享说明与实际图片依赖一致。
3. 分发：Remotion 直接依赖固定同一版本；MIT LICENSE、第三方 notices 与源码获取说明随包分发。
4. 文档：GitHub 与 npm 共用核心介绍，npm 链接使用公开地址；变更记录对应发布版本。
5. CI：检查标签与插件版本，打包一次，隔离安装验证，npm 与 GitHub Release 使用同一份包；重跑先核对已有产物。
6. 验收：全新 DSH profile、真实目录案例、异常引导、配音听感、取消清理、同目录并发与跨平台覆盖。

ZIP 导出、完整实时进度、并发调度、渲染引擎迁移和新场景不纳入本版。

## 发布步骤

依次完成引用边界、HTML、分发与许可、文档与流水线。各批跑针对性检查；候选版前通过 `pnpm typecheck`、`pnpm test`、`pnpm run check` 和插件 `prepack`。

候选版使用 `0.3.1-rc.N` / npm `next`。真实验收通过后生成正式 `0.3.1` 包，最终包仍须隔离安装验证；同一版本的 npm 包与 Release 附件必须字节一致。

发布时记录提交、版本、包校验和和验收环境。已有 npm 版本不可覆盖；同版本重跑只能复用并核对原包，补齐缺失步骤。

## 尚待确认的外部条件

- 已决定公开 GitHub 仓库，文档、示例与 Issues 作为入口。
- MIT 版权主体采用用户指定的 `Luan_Fuzi`。
- npm Trusted Publisher 已配置，OIDC 直接发布通过；候选版已进入 `next`。未授权独立 dist-tag 管理。
- 真实 DSH 环境及完整验收结果。未验证项不能写成通过。

## 候选版后的执行与通过条件

当前宿主为 DSH 0.2.0-rc.2。先用独立 DSH_HOME 和测试 profile 验证安装；随后按用户确认，在现有 desktop profile 的新对话中完成设置与创作，结束后恢复临时偏好。测试输入采用公开仓库的独立副本。每项记录宿主、插件版本、操作、日志或产物路径、通过／失败／未验证及原因。实际进展见[验收记录](../releases/2026-10-11-0.3.1-acceptance.md)：步骤 1 的安装与加载通过，历史下载错误 (23) 未复现；步骤 2–3 已完成，步骤 4 的程序与页面检查通过，整片播放待用户确认，步骤 5 待执行。

| 顺序 | 工作 | 通过条件 |
|---|---|---|
| 1 | 新 profile 安装与宿主加载 | 候选包安装成功，宿主启动并加载插件；记录实际失败与恢复步骤。历史下载错误 (23) 若未复现，保留原因未确认的结论。必要时用 0.3.0 做基线，区分宿主／下载环境与插件问题。依赖构建审批按实际提示处理；下载超时或缓慢时遵守镜像和代理规则。 |
| 2 | 在真实 DSH 验收设置页 | 创作偏好、内置／自定义风格、配音引擎和音色显示正确；修改和保存可用，重启后保留；工具收到对应偏好。 |
| 3 | 对公开真实目录完成创作及独立评审 | DSH Agent 生成新的 digest 和讲稿；机器校验、独立事实与表达评审通过；当前 revision 的回执有效；正式 HTML 生成成功，来源和重点可核查。 |
| 4 | 配音、视频与听感验收 | 默认引擎真实合成并生成完整 MP4；程序核对时长、缓存与产物记录；人工检查发音、停顿、截断、字幕和节拍，检查桌面与窄屏页面。记录实际验证的引擎，不把未测引擎写成通过。 |
| 5 | 生成正式 0.3.1 并发布 | 更新版本号、README 和变更记录，重新生成正式 tarball；必要检查与三平台隔离安装通过；npm latest 与 GitHub Release 发布同一份包，下载核对字节及校验和。 |

若验收发现产品代码需要修复，修复后发布 rc.2 并复验受影响步骤。安装启动、关键设置、内容评审或配音成片仍有阻塞时，不发布正式版。宿主或下载环境问题先按证据处理，不预先认定为插件缺陷。

代码、程序检查、产物生成和证据整理由 agent 执行；最后的听感、画面与内容是否适合交付由用户确认。验收后更新发布记录，保留未验证范围。
