# dsh-foldercast

把任意**人类可读的目录**变成讲解视频的 DSH 插件。探目录与写讲稿是 agent 的事
（skill 里写了工作流与判据）；这个包负责精确、重复、可验证的执行部分：讲稿校验、
按需素材转换、配音与逐帧渲染。

## 0.3.0（2026-10-11）

- 视频与默认 HTML 共用瑞士风格、编辑设计风格和科技风格，可查看内置创作指导。
- 自定义风格可填写名称、效果描述和基础视觉预设；描述指导创作，实际画面使用现有模板。
- 创作与沟通偏好支持受众、重点、深度及视频和导览页阅读预算，已有上下文和本次要求优先。
- 配音引擎与音色使用下拉选择，显示默认音色；修复跨引擎继承音色和项目 `.env` 读取。
- 正式产出绑定评审版本，音频支持逐场缓存与断点续跑，产物记录输入与输出版本。

升级兼容说明见下面的「从 0.2.0 升级」。

## 安装

从 GitHub Release 安装已构建的 0.3.0 包。私有仓库需要先用有访问权限的 GitHub 账号登录 `gh`，下载后安装本地包：

```bash
gh release download v0.3.0 --repo Luan-Fuzi/foldercast --pattern dsh-foldercast-0.3.0.tgz --dir ./foldercast-release
dsh plugin --profile <profile> add "$(pwd)/foldercast-release/dsh-foldercast-0.3.0.tgz"
```

仓库公开后，也可以直接用下载地址安装：

```bash
dsh plugin --profile <profile> add https://github.com/Luan-Fuzi/foldercast/releases/download/v0.3.0/dsh-foldercast-0.3.0.tgz
```

装完在插件管理页能看到「目录放映」，对话里说「把这个目录讲一遍」就会触发 `foldercast_cast`。

## 它做什么

插件注册**一个工具**与**一个 skill**：

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 校验（有讲稿才跑） | schema、场景字段、引用路径存在性、字幕切分 | 结构化问题清单 |
| 页面（显式 `page: true`） | 讲稿与素材 → 零 JS 的 HTML 导览页 | `<目录>/.foldercast/out/page.html` |
| 配音（显式 `voice: true`） | 逐场景云端合成（edge / mimo）+ `ffprobe` 实测时长 | `<目录>/.foldercast/audio/`、`durations.json` |
| 渲染（显式 `render: true`） | 按需转换引用的素材 → Remotion 出片 | `<目录>/.foldercast/out/video.mp4` |

**页面、渲染与配音默认都不跑**，必须显式要求。正式产出需要与当前输入匹配的评审回执；`draft: true` 允许工作草稿。校验返回 `revision`，末轮独立评审通过并写好 `review.md` 后，传 `reviewRevision: revision` 记录回执。传参表示 agent 声明评审通过。程序检查版本和报告哈希，不解析自然语言结论，不证明内容正确。revision 对讲稿、digest 与直接引用文件计算内容哈希；引用目录使用文件名、大小和修改时间，digest 的文件总数抽查也参与。它不覆盖全部源目录正文或软件版本。

`artifacts.json` 记录产物的输入版本、实际参数、文件依赖与输出哈希。current 仅表示仍匹配记录中的输入与参数，不表示内容正确或适合新设置。场景音频按旁白、provider、音色、风格、格式等输入复用；合成输入改变或音频被改动后自动失效，逐场记录保存在 `audio/cache.json`，支持断点续跑。只改画面不需要重合成；改讲稿中的 voice 配置需重跑 voice，实际请求相同的场景仍可复用。渲染拒绝过期、缺少新版本记录或整条音轨不完整的 durations。HTML 与视频共享素材准备和场景内容，输出形式不同。HTML 超过图片内联预算时使用相对路径，转发需要附带被引用素材并保留相对位置；Office / PDF 页图与视频封面指向准备产物。

主 skill 给工作流，场景与评审详细参考随包位于 `scripts/references/`。直跑 CLI 默认生成草稿，`--approved` 检查当前评审回执。

另有文本提取入口：把 Office / PDF 的内容提取成 Markdown 打到 stdout，给 agent 通读。
在安装包根目录运行 `node lib/scripts/assets/text.js <文件>`；仓库开发时运行 `pnpm text <文件>`。

## 从 0.2.0 升级

讲稿与 digest 的 schema 版本不变。旧 `review.md` 需重新评审并记录当前回执。没有逐场缓存记录的旧音频，第一次重跑 voice 会重配；旧 durations 缺少新版本记录，不能直接用于渲染。

已有讲稿和旧风格名称继续接受，不自动重写。新设置影响后续工具调用和创作，已有产物不会自动重做。安装或更新插件后重启 DSH，使入口和设置页加载新版本。

## 设置页

设置窗口左侧的「目录放映」页分为创作与沟通、美术风格、配音、高级设置四组：

| 组 | 配置 | 行为 |
|---|---|---|
| 创作与沟通 | 沟通方式、受众、讲述重点 | 按需询问（默认）/ 先沟通目标 / 直接规划；已有回答不重复追问 |
| 创作与沟通 | 深度、时长与提示词 | 可展开填写讲述深度、视频目标分钟数、导览页目标阅读分钟数与创作沟通提示词；留空由 Agent 判断 |
| 美术风格 | 整体美术风格 | 瑞士风格（Swiss Style，默认）/ 编辑设计风格（Editorial Design）/ 科技风格（Tech-inspired Design）/ 自定义风格；可展开查看创作指导 |
| 美术风格 | 自定义风格 | 填写可选名称和“想要的效果”，描述会进入 Agent 创作指导；基础视觉预设控制实际配色、字体与卡片观感 |
| 美术风格 | 自定义美术提示词 | 引导写稿模型的场景设计、选材和节拍；需重新创作并评审讲稿后生效 |
| 配音 | 配音引擎、音色 | edge（默认）/ mimo；音色可选预置或自定义，默认名称直接显示 |
| 配音 | 朗读风格 | 仅 mimo 支持；edge 下禁用。mimo 仍通过环境读取 MIMO_API_KEY |
| 高级设置 | 浏览器路径、渲染并发数 | 默认自动检测浏览器、并发 1；并发范围 1–8 |
| 高级设置 | 导览页单独风格 | 默认跟随整体美术风格，也可单独选择瑞士风格 / 编辑设计风格 / 科技风格 |

设置保存后，后续工具调用读取新值。工具返回 `creativePreferences`，Agent 先结合本次要求与已有回答规划，只询问影响取舍的缺项。默认受众、重点、深度和目标分钟数都是参考；需要调整时说明理由。时长设置不会直接传给渲染器缩放画面或截断音频，配音仍以实测时长为准。导览页目标用于估计阅读量，不是实际阅读计时；当前 HTML 与视频共用场景，预算不一致时需讨论内容展开程度。采用的偏好、预算依据和省略范围记入 `digest.notes`，已有讲稿不会自动改写。

选择内置风格时，工具返回的 `visualPreferences.style` 使用设计名称，`stylePrompt` 包含中文名、英文设计术语与内置创作指导，`prompt` 保留用户补充。写稿模型结合本次要求，把采用的名称和美术指导写入 `script.visual`。讲稿中的风格优先于插件默认值；直接 CLI 的 `--style` 可显式覆盖。已有讲稿不会因为提示词变化而自动改写，修改讲稿后需重新校验与评审。预设控制配色、字体与卡片观感；提示词控制创作选择，不直接执行为 CSS，也不增加现有 11 种场景之外的自由版式。

选择「自定义风格」后，原提示词输入框显示为「想要的效果」，必须填写后才能在设置页保存。工具的 `stylePrompt` 包含自定义名称和效果，保留原始 `prompt`，并单独返回 `baseStyle`。不会附加基础预设的内置创作指导。模型将本次名称、效果与基础预设保存在 `script.visual`；名称留空时使用「自定义风格」，基础预设缺省为瑞士风格。自由描述引导创作，不保证现有模板能精确实现任意字体、颜色或自由布局。当前只有一套自定义风格设置，不提供多套风格的保存和管理。

旧 `page.style` 配置继续作为 HTML 的独立覆盖保留；选择「跟随整体美术风格」后可与视频采用同一预设。旧讲稿没有 `visual` 时使用设置页默认值；未另设默认值或直接使用 CLI 时仍用瑞士风格，不需升级 `foldercast` schema 版本。旧名称「素稿 / 杂志 / 夜幕」可继续输入，读取时归一为「瑞士风格 / 编辑设计风格 / 科技风格」；设置页、工具返回与产物报告使用新名称，不改写旧讲稿或其哈希。

## MiMo API Key

设置页选择 `mimo` 配音引擎。本版不提供 API Key 输入框，密钥通过 `VoiceEnv.secret("MIMO_API_KEY")` 读取，优先级为：

1. 启动 DSH 或 CLI 的进程环境变量 `MIMO_API_KEY`。
2. 被讲解目录的 `.env`。
3. `$DSH_HOME/.env`，未指定 `DSH_HOME` 时为 `~/.dsh/.env`。

在对应 `.env` 中添加一行（下面是占位示例）：

```dotenv
MIMO_API_KEY=替换为你的密钥
```

`.env` 的修改在下一次配音时读取；若修改的是启动环境变量，需要重新启动 DSH。密钥不写入插件设置、日志、报告或 JSON 产物。宿主凭据存储本版不直接读取。缺少密钥时，MiMo 配音返回退出码 4 和配置说明，HTML 生成不需要密钥。

## 只生成 HTML

对话中明确要求「只生成 HTML 导览页」，工具只启用 `page: true`。已有讲稿的配色和字体可以直接换预设；选材、叙事或长度变化需要先修改讲稿。

仓库内快速生成工作草稿：

```bash
pnpm page <目录> --style 编辑设计风格
```

安装包根目录的等价命令为 `node lib/scripts/page/main.js <目录> --style 编辑设计风格`。
这一步不跑配音或视频渲染。正式产出仍需当前评审回执，CLI 加 `--approved`。

## 依赖

阶段代码以编译后的 JS 随包分发（`lib/scripts/`），创作参考位于 `scripts/references/`；仓库开发直接运行 TypeScript。外部命令按需降级：

| 依赖 | 用途 | 缺了会怎样 |
|---|---|---|
| Node `^22.19.0 \|\| >=24.0.0` | 安装包运行 JS；仓库开发运行 TypeScript | 硬条件，缺了不能用 |
| 浏览器（Chrome / Chromium / Edge） | Remotion 渲染 | 只影响出片；校验与页面照常 |
| 网络 | 配音的云端 TTS（edge / mimo） | 不配音，出静音片 |
| `ffmpeg` / `ffprobe` | 音频转换与实测时长、视频封面 | 配音不可用；渲染仍能出静音片 |
| `@deepseek-ai/libreoffice-kit`（optionalDependency） | Office / PDF 逐页图 | 这两类没有页图；文本提取照常 |
| `sips`（macOS 自带） | 图片缩放 | 回退到 ffmpeg |

缺失时工具会返回**可操作的说明**（缺什么、怎么装），而不是一个裸错误。
