# 独立评审参考

评审者输入：被讲解目录（只读）、digest.json、script.json、校验 revision 和本文件。复评另提供上轮 review.md。不要依赖写稿人的选择理由证明讲稿合理。

## 两阶段核查

1. 事实层：对照源目录核查 digest 的事实、计数口径、路径和原文摘录。深度围绕本次讲述目标，不要求全面盘点所有文件。
2. 讲述层：对照已核查的 digest 检查 script；可疑断言回到源文件核查。不要把第一阶段通过理解为所有数字永久正确。

逐项给出结论和证据（文件路径、原文片段、行号或计数方法）：

| 项目 | 要核查什么 |
|---|---|
| 事实 | 断言是否有依据；推断、不确定性是否明确；有没有把改写当成原文 |
| 数字 | 核查重要数字与比较结论，明确统计口径；密集数字场景增加抽查 |
| 重点 | 是否回答受众需要理解的问题，重要性不能只按文件体积判断 |
| 遗漏 | 是否缺少理解结论所需的背景、关键关系或限制 |
| 结构 | 顺序能否帮助理解，每场是否有明确主题；不强制总—分—总 |
| 表达与展示 | 旁白能否直接读；画面与旁白是否互相支撑；逐条处理机器 warning |

density-out-of-band、layout-monotony、摘录行数与目标时长等提示需要说明处理意见，可保留有依据的例外。看工作草稿有助于检查画面；密度指标不能证明字号、裁切或溢出符合要求。

## 结论与复评

将每轮结论写入 `.foldercast/review.md`，注明第 N 轮、revision、通过 / 不通过、证据与剩余建议。发现编造、错误关键数字或无法确认的核心事实时不通过。非关键创作建议可以带建议通过；待确认项写清缺少什么证据。

修复后核对上轮每项问题，并抽查改动场景是否引入新错。digest 改动时重新核查事实层。通过后写稿人用本轮 revision 记录回执，不能拿新校验的 revision 代替未评审的版本。

程序检查回执是否对应当前输入和报告。程序不理解评审结论，不证明事实正确，也不替代独立评审。
